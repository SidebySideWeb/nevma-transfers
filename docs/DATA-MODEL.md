# Data model — Postgres (Supabase)

Source of truth: `packages/db/migrations/0001` to `0006`, the project's own `0007` (rate limits) and `0008` (payments flow) written during the build, `0009` (booking reference prefix `EP-`, 1 Nov), `0010` (VAT), `0011` (office bookings), later fleet/VAT/extras migrations, and `0017` (booking reference prefix `ELP-`, 2 Nov). Tests: `packages/db/tests/` (run against a real PostgreSQL 16, see `packages/db/README.md`). A change is a new numbered migration plus an update to this file and the tests.

Conventions: money in integer cents (`int`, `check >= 0`), currency `char(3)` default `EUR`; times `timestamptz`; time ranges `tstzrange` `[from, to)`; codes and keys are lowercase slugs (`^[a-z0-9]+(-[a-z0-9]+)*$`).

## Bookings and payments (0003)

### `bookings`

| Column | Notes |
| --- | --- |
| `id`, `reference` | reference `ELP-XXXXXX` (alphabet without 0, O, 1, I), unique, generated by default; 0017 changed the prefix from `EP-`/`TEM-`, older rows keep their original prefix |
| `booking_type`, `class_id`, `vehicle_id` | `vehicle_id` is set by the office after confirmation |
| `from_zone_id`, `to_zone_id`, `pickup_address`, `dropoff_address` | `to_zone_id` and `dropoff_address` only for transfers |
| `pickup_at`, `hours`, `duration_minutes`, `blocked_range` | `duration_minutes` = route duration (transfer) or `hours * 60` (hourly); `blocked_range = blocked_range_for(pickup_at, duration_minutes, class buffer)` |
| `passengers`, `luggage`, `flight_number`, `notes` | |
| `customer_name`, `customer_email`, `customer_phone` | personal data: never logged |
| `base_price_cents`, `price_cents`, `currency` | copied at creation: base = zone price or rate x hours; `price_cents` = base + extras |
| `status`, `hold_expires_at` | see the state machine in `docs/BOOKING-RULES.md` |
| `payment_status`, `viva_order_code` (unique) | |
| `invoice_status`, `invoice_company`, `invoice_vat`, `invoice_tax_office`, `invoice_address`, `invoice_number` | invoices are issued by hand |
| `vip_security`, `security_notes` | flag kept in step with the `vip-security` extra by trigger; notes by the office |
| `cancel_token_hash` (unique) | SHA-256 hex of the cancel-link token |
| `reminder_sent_at`, `cancelled_at`, `created_at`, `updated_at` | `updated_at` set by trigger |

Constraints:
- `bookings_type_fields`: transfer needs `to_zone_id`, `dropoff_address`, `hours is null` and two different zones; hourly needs `hours` 1–24, no drop-off, `duration_minutes = hours * 60`. Per-class limits (`hourly_rates.min_hours`/`max_hours`) are checked by the API.
- `bookings_range_covers_trip`: the blocked range covers pickup to pickup + duration.
- `bookings_price_covers_base`: `price_cents >= base_price_cents`.
- `bookings_no_vehicle_overlap` (exclusion, `btree_gist`): one vehicle can never carry two overlapping active (`pending`, `confirmed`, `assigned`) bookings.

### `booking_extras`
`booking_id`, `extra_id`, `quantity`, `price_cents` (copied at creation). Trigger `booking_extras_vip` keeps `bookings.vip_security` true exactly when the booking has the `vip-security` extra.

### `payments`
`id`, `booking_id`, `kind` (`payment`, `refund`), `status` (`pending`, `succeeded`, `failed`), `amount_cents` (> 0), `viva_order_code`, `viva_transaction_id` (unique: duplicate webhooks cannot record twice), `idempotency_key` (unique: a repeated refund request returns the first result), `raw` (verified Viva transaction JSON; never log it), `created_by` (staff user for admin refunds), `created_at`.

Trigger `payments_refund_limit`: locks the booking and rejects any refund (`pending` or `succeeded`) that would make refunds exceed succeeded payments (`refund_exceeds_paid`, SQLSTATE 23514). Failed refunds are recorded but do not count.

### Functions
- `blocked_range_for(pickup timestamptz, duration_minutes int, buffer_minutes int) → tstzrange`: real elapsed minutes, so DST nights are correct.
- `generate_booking_reference() → text`.

## Holds, settings, staff (0004)

| Table | Columns | Rules |
| --- | --- | --- |
| `settings` | `key`, `value` (jsonb), `description`, `is_demo` | rows: `hold_minutes` 20, `min_lead_minutes` 120 (DEMO), `cancel_window_hours` 24 (DEMO), `max_active_holds_per_visitor` 2, `timezone` "Europe/Athens". Read with `setting_int(key)`. |
| `staff` | `user_id` (Supabase Auth user), `email`, `name`, `created_at` | the allow-list for the admin; FK to `auth.users` added in 0006 |
| `slot_holds` | `id`, `class_id`, `visitor_key`, `blocked_range`, `status` (`active`, `converted`, `expired`, `released`), `booking_id`, `created_at`, `expires_at` | an active hold blocks one vehicle of the class until `expires_at` |

Functions:
- `class_availability(class_id, range, exclude_booking default null) → int`: active vehicles not blocked in the range, minus overlapping `confirmed`/`assigned` bookings and `pending` bookings whose hold has not expired, minus active unexpired holds not yet converted. Expired holds never count, whether or not the cron has run.
- `create_hold(class_key, pickup, duration_minutes, visitor_key) → slot_holds`: locks the class row (`for update`), checks the visitor's active holds (`too_many_holds`), checks availability (`unavailable`), inserts a hold for `hold_minutes`. Raises `invalid_request` for an unknown class. Two visitors can never both take the last vehicle (test AC-05).
- `expire_holds() → int`: marks ended holds `expired` and unpaid `pending` bookings past their hold `expired`.

## Security (0005)

- RLS enabled on all 14 tables; `anon` has no rights on any table.
- `is_staff()` (security definer): `exists (select 1 from staff where user_id = auth.uid())`.
- Staff (`authenticated` + `is_staff()`): read every table; insert/update/delete `vehicle_classes`, `vehicles`, `zones`, `zone_routes`, `zone_prices`, `hourly_rates`, `extras`, `blocked_slots`; update `settings` values.
- Bookings: staff may update only `vehicle_id`, `status`, `security_notes`, `invoice_status`, `invoice_number` (column grants). Trigger `bookings_staff_guard` allows staff status changes only `confirmed→assigned`, `assigned→confirmed`, `assigned→completed`; cancellation goes through `/api/internal/cancel`.
- `payments`, `slot_holds`, `booking_extras`, `staff`: read-only for staff; written by the server (service role) only.
- `service_role` bypasses RLS (Supabase default); used only by `apps/web` server code.

## Scheduled jobs (0006, Supabase only)

`pg_cron` job `tem-expire-holds` runs `expire_holds()` every minute. Reminder emails are sent by Vercel Cron (`/api/cron/reminders`), not by the database.

## 0010 — VAT (1 Nov 2026)

Rules: `docs/BOOKING-RULES.md` §2. Every customer-facing price is final (VAT included). The VAT share is shown only as a price analysis on the review step and in the confirmation email.

| Object | What |
| --- | --- |
| `settings.vat_rate_bp` | basis points (2400 = 24%), DEMO until the accountant confirms (O18) |
| `bookings.vat_rate_bp` | copied from settings at insert by trigger `bookings_set_vat_rate` (never set by the API) |
| `bookings.vat_cents` | generated always: `price_cents − round(price_cents × 10000 / (10000 + vat_rate_bp))` |
| `vat_from_gross(gross, rate_bp)` | same formula as a SQL helper |

Staff column grants stay unchanged: staff cannot update VAT fields.

## 0012 — Setup guards (1 Nov 2026)

Rules: `docs/FLEET-SETUP.md`. Adds `vehicles.note` (staff-only). Triggers on `vehicle_classes`, `vehicles`, `zones`, `extras`: keys and codes fixed once used (`in_use`), no delete of anything with history (switch off or retire), no status or class change for a vehicle with future bookings (`has_future_bookings`), built-in extras `vip-security` and `night-surcharge` kept; unique vehicle labels (`vehicles_label_key`).

## 0013 — Customer list (1 Nov 2026)

`customer_summaries` view (security invoker, staff only through RLS): one row per customer with `bookings_count`, `last_pickup_at`, `has_vip_security`, `paid_cents` (succeeded payments minus succeeded refunds).

## 0014–0015 — Fleet feed fields (1 Nov 2026)

`docs/FLEET-FEED.md`. Adds `is_demo` on reference tables, `extras.applies_to` (`text[]` of `transfer` / `hourly`) and `extras.max_quantity`. `create_booking_from_hold` counts duplicate extra codes as quantity and rejects extras outside `applies_to` or above `max_quantity`.

## 0016 — `booking_type` vs `applies_to` cast (2 Nov 2026)

`create_booking_from_hold` compares `h.booking_type::text` to `extras.applies_to` (`text[]`). Without the cast Postgres raises `operator does not exist: booking_type = text`.

## 0017 — Booking reference `ELP-` (2 Nov 2026)

`generate_booking_reference()` returns `ELP-` + 6 unambiguous characters. The `bookings.reference` check accepts `ELP-`, `EP-` and `TEM-` so older rows remain valid.

## 0018 — Automatic vehicle when a class has one vehicle (2 Nov 2026)

Rules: `docs/FLEET-SETUP.md` ("Automatic vehicle"). `bookings.vehicle_auto_assigned` (true when the rule set the vehicle; cleared when staff change the vehicle). Setting `auto_assign_single_vehicle` (default `true`). `single_free_vehicle(class, range, booking)` returns the class's only `active` vehicle when it is free for the range (no blocked slot, no other pending/confirmed/assigned booking), else null. Trigger `bookings_auto_assign` (before insert or update of status, vehicle_id): when a booking becomes `confirmed` (insert, or from `pending`/`expired`) without a vehicle, it sets that vehicle; the status stays `confirmed`. `auto_assign_backfill(class default null) → int` (staff or server; run once by the migration) assigns waiting future confirmed bookings. Tests: `packages/db/tests/auto-assign.test.mjs`.
