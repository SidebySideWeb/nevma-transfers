## 3. Data split

- **Sanity:** `siteSettings`, `uiStrings`, `vehicleClass` (photos, copy, specs, SEO), `page` (home and legal pages). Content only. See `docs/CONTENT-MODEL.md`.
- **Postgres:** vehicle classes (capacity, luggage, buffer), vehicles, zones, routes, zone prices, hourly rates, extras, blocked slots, bookings, booking extras, payments, holds, settings, staff. See `docs/DATA-MODEL.md`.
- **Join:** only the vehicle class `key` (for example `v-class`). The admin shows a warning for any class that exists on one side only; the booking flow hides a class with no Sanity content and logs it.

## 4. Request flows

```
Visitor ── /book (React island) ── GET  /api/booking-options          zones, classes, hour limits, extras
                                   POST /api/quote                    price + availability per class (no lock)
                                   POST /api/holds                    create_hold(): class row lock, 20-min hold
                                   POST /api/bookings                 one transaction: re-check, price, insert pending booking,
                                                                      convert hold; then create the Viva order
          review step shows the stored total ── "Pay securely" ── Viva hosted checkout
Viva ── redirect ── /booking/confirmed?s=<orderCode>  page polls GET /api/booking-status (shows "confirming" until the webhook lands)
Viva ── POST /api/webhooks/viva ── fetch the transaction from Viva ── record payment (unique transaction id) ── confirm booking ── emails
Customer ── /booking/cancel/<token> ── POST /api/bookings/cancel ── refund per policy ── emails
Office ── apps/admin ── Supabase (staff RLS) for assignment, notes, invoices, prices, slots
                   └─ signed POST /api/internal/refund | /api/internal/cancel  (Viva and emails stay in step)
Vercel Cron ── GET /api/cron/reminders every 15 min (24-hour reminder, once)
pg_cron ── expire_holds() every minute (tidy-up only; queries never trust stale holds)
```

Rendering: home and legal pages are prerendered from Sanity at build time. A Sanity webhook (filter: published documents of types `page`, `siteSettings`, `uiStrings`, `vehicleClass`) POSTs to the Vercel deploy hook of the `tem-web` project so the site rebuilds on content publish (hook URL is set in prompt 13; create the webhook in the Sanity project → API → Webhooks). `/book` is a static shell with the island. `/booking/*` and `/api/*` render on demand.

## 5. Security model

- RLS on every table; `anon` has no table rights; staff are users listed in `staff` (checked by `is_staff()`); staff may update only `vehicle_id`, `status` (confirmed↔assigned→completed), `security_notes`, `invoice_status`, `invoice_number` on bookings.
- The web API uses the Supabase **service role** on the server only. The admin never has it: it uses the anon key plus the signed-in staff session.
- The Viva secrets exist only in `apps/web`. The admin reaches Viva only through `/api/internal/*`, signed with HMAC-SHA256 over `timestamp + "." + raw body` (`ADMIN_TO_WEB_SIGNING_SECRET`), rejected if older than 5 minutes, with an idempotency key.
- Public write endpoints (`/api/holds`, `/api/bookings`, `/api/bookings/cancel`) need Turnstile and are rate limited (per IP and per visitor cookie `tem_vid`).
- Cancel links carry a random 32-byte token; the database stores only its SHA-256 hash.
- Logs carry ids and error codes only: no names, emails, phone numbers, tokens or Viva payloads.
- `Content-Security-Policy` (self, Sanity CDN images, Cloudflare Turnstile script/frame, form/navigation to Viva checkout hosts), `Strict-Transport-Security`, `X-Frame-Options: DENY` on `/book` and `/booking/*`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` locking camera/mic/geolocation — set in `apps/web/vercel.json` (prompt 12).

## 8. Budgets and targets

- Public pages: LCP under 2.5 s, INP under 200 ms, CLS under 0.1 (mobile, 4G profile).
- Pages other than `/book` ship no framework JavaScript. The booking island: under 100 KB gzip (PROPOSED).
- API: p95 under 500 ms excluding Viva calls.

## 9. Backups

Supabase Pro daily backups, plus a weekly encrypted export of the Sanity dataset and a dump of the bookings database to the agreed storage (prompt 13). A restore test runs before launch.
